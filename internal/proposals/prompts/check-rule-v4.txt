You draft one automated check for an architecture decision. The check runs when an AI coding agent proposes an edit, and denies the edit when it breaks the decision. A person reviews the check before it is used.

Answer with one JSON object and nothing else, in this shape:
{"difference":"What every edit to deny has and no edit to allow has.","candidates":[{"rules":[{"when":[{"field":"path","op":"suffix","value":".go"}],"message":"What the decision forbids."}]}]}

First write "difference": compare the edits to deny with the edits to allow, field by field, and name exactly what tells them apart. Then write two candidates, each a complete check that tests that difference in its own way, such as with another field, op, or regex. The first candidate that passes every edit is proposed.

An edit has these fields:
- tool: write, edit, patch, delete, shell, or working-tree.
- path: the file, from the repository root. Empty for a shell command.
- content: the whole file after the edit.
- added: only the text the edit adds.
- command: the shell command. Empty for a file edit.

A candidate denies an edit when any of its rules holds, and a rule holds when every condition in "when" holds. Use one to three rules of at most five conditions. To deny either of two cases, write a rule for each. To allow an exception, add a condition for the exception with "not": true.

A condition has a field, an op, a value, and an optional "not": true. "not" is never an op. Use "not" only for an exception, or for text that must be present. The ops:
- equals, prefix, suffix, contains: the field is, starts with, ends with, or holds the value, as plain text with no backslash, including quotes, * and parentheses.
- glob: the whole field matches a glob; * stays inside one directory, ** crosses them.
- regex: an RE2 pattern matches anywhere in the field; (?i) ignores case. In JSON, write each backslash twice, as in "\\s+".

prefix and suffix suit path: a file kind by name or extension, such as "Makefile" or ".py", and a directory, such as "docs/". For text in content, added, or command, use contains or regex. A missing field is the empty string. Use "added" for text the edit introduces and "content" for what the whole file must hold. Keep the check as general as the decision, not tied to the paths of the examples: it also runs on edits you do not see.

Examples.
Decision: "Terraform never makes a bucket public."
{"difference":"The edits to deny add acl = \"public-read\" to .tf files.","candidates":[{"rules":[{"when":[{"field":"path","op":"suffix","value":".tf"},{"field":"added","op":"contains","value":"acl = \"public-read\""}],"message":"Terraform never makes a bucket public."}]},{"rules":[{"when":[{"field":"path","op":"suffix","value":".tf"},{"field":"added","op":"regex","value":"acl\\s*=\\s*\"public-read\""}],"message":"Terraform never makes a bucket public."}]}]}
Decision: "Agents never run terraform destroy."
{"difference":"The commands to deny run terraform destroy.","candidates":[{"rules":[{"when":[{"field":"command","op":"regex","value":"terraform\\s+destroy"}],"message":"Agents never run terraform destroy."}]}]}
Decision: "Generated code under gen/ is not edited, except gen/README.md."
{"difference":"The edits to deny change files under gen/ other than gen/README.md.","candidates":[{"rules":[{"when":[{"field":"path","op":"prefix","value":"gen/"},{"field":"path","op":"equals","value":"gen/README.md","not":true}],"message":"Generated code under gen/ is not edited."}]}]}
Decision: "Shell scripts start with set -euo pipefail."
{"difference":"The edits to deny are .sh files whose content lacks set -euo pipefail.","candidates":[{"rules":[{"when":[{"field":"path","op":"suffix","value":".sh"},{"field":"content","op":"contains","value":"set -euo pipefail","not":true}],"message":"Shell scripts start with set -euo pipefail."}]}]}
