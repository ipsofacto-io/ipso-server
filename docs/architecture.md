# Control-plane architecture

Overview of the internal packages, security boundaries, background jobs, and ADR references inside `ipso-server`.

## Registry and audit (`internal/registry`, `internal/audit`)

- **Bitemporal registry:** Stores decision versions, the scope tree, and its closure table. `internal/registry` resolves in-force decisions for a repository, path, and environment ([ADR-0051](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0051-scope-model-and-resolution.md)).
- **Supersession and baselines:** Records supersessions (closing prior decisions) and violation fingerprint baselines per decision and repository ([ADR-0052](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0052-supersession-and-grandfathering.md)).
- **Waivers:** Records scoped waivers of at most 90 days and marks matching failures as waived while both waiver and decision cover the valid time. `Notify` writes `ticket_ref` notices at 14, 3, and 0 days before expiry ([ADR-0054](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0054-waivers-with-expiry.md)).
- **Audit queries:** `internal/audit` answers the five compliance audit questions via `GET /v1/audit/*`, scoped strictly to the token's tenant ([ADR-0055](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0055-audit-query-api.md)).

## Identities and access control (`internal/identity`, `internal/authn`, `internal/authz`, `internal/login`)

- **Principals and sponsors:** `identity.principal` stores humans and AI coding agents. Every agent requires a human sponsor in the same tenant, and database constraints reject agents as approvers of waivers or proposals ([ADR-0076](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0076-agent-identities.md)).
- **Tamper-evident action log:** `identity.action_log` records principal actions with the responsible human in a per-tenant hash chain. Admins and auditors read it as JSON Lines via `GET /v1/audit-log` (up to 1,000 lines / ~1 MiB per page, paginated via `seq`) and verify integrity with `ipso-server audit-log verify` ([ADR-0126](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0126-hash-chained-action-log.md), [audit-log.md](audit-log.md)).
- **Token and role mapping:** `identity.login` maps OIDC issuer + subject to a principal via `identity.PrincipalFor` ([ADR-0093](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0093-single-tenant-token-mapping.md)). `identity.role_binding` assigns one of seven roles tenant-wide or per scope subtree; the database rejects any role other than `agent` for agent principals ([ADR-0108](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0108-role-policy.md), [roles.md](roles.md)).
- **Browser sign-in and invitations:** Enabled when `IPSO_PUBLIC_URL` and `IPSO_LOGIN_PROVIDERS` are set. `internal/login` supports Google, Microsoft, generic OIDC, and GitHub using PKCE, `state`, and nonce, creating new people only from an open admin invitation (`POST /v1/invitations`) ([ADR-0099](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0099-browser-login-sessions.md), [ADR-0127](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0127-invitations.md), [login.md](login.md)). Sessions live in `identity.session` behind an 8-hour `HttpOnly; Secure; SameSite=Strict` `__Host-ipso-session` cookie with cross-origin state-change protection. ipso stores no passwords.

## Control-plane API and web app (`internal/api`, `web/`)

- **Routes and OpenAPI:** `internal/api` serves the OpenAPI 3.1 API ([api/openapi.yaml](../api/openapi.yaml), [ADR-0090](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0090-control-plane-api.md)):
  - Reads: `POST /v1/resolve` ([ADR-0092](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0092-resolve-answer-once.md)), `GET /v1/decisions`, `/v1/decisions/{ref}`, `/v1/scopes`, `/v1/waivers` (bitemporal `valid`/`known`), `GET /v1/premise-reasons`, `GET /v1/premise-hosts` ([ADR-0117](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0117-premise-reads.md)), review queues, and audit routes.
  - Verdicts: `POST /v1/verdicts` accepts GitHub Actions OIDC tokens; `GET /v1/verdicts` evaluates v2 report digests against recorded baselines ([ADR-0102](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0102-signed-verdict-uploads.md), [ADR-0122](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0122-baseline-on-verdict-reads.md), [verdicts.md](verdicts.md)).
  - Human-only writes ([ADR-0109](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0109-control-plane-write-routes.md)): scopes, supersessions, grandfather periods, baselines, waivers, proposal and check-proposal approvals ([ADR-0116](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0116-check-proposal-approval.md)), premise clearances, and premise allowlist updates.
- **Guard and limits:** Every request runs through a single authn/authz guard (embedded offline Rego policy). Tenant and principal come strictly from the token (query params `tenant`/`tenant_id` return `400`). Writes and agent calls are transactionally logged to `identity.action_log` (failing closed if logging fails). Limits: 10s request deadline, 1 MiB body cap, 4 MiB response cap, 10 req/s (burst 20) per tenant per process. `GET /healthz` returns `204` outside the guard.
- **Startup checks (`--role=api`):** Verifies `internal/rls.Check`, confirms the `IPSO_TENANT_ID` row exists, fetches HTTPS OIDC discovery metadata, and refuses to start if `IPSO_MIGRATE_DATABASE_URL` is set ([ADR-0094](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0094-the-api-role.md)).
- **Contract tests and web SPA:** Contract tests verify `api/openapi.yaml` matches mounted routes and integration traffic; `ci / pact` verifies the consumer pact in [api/pacts/ipso-web-ipso-server.json](../api/pacts/ipso-web-ipso-server.json) ([ADR-0091](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0091-api-contract-tests-and-pact.md)). `web/` builds into `internal/webapp/dist/app` and is embedded by `go build` with a strict self-only CSP ([ADR-0106](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0106-web-app-stack-and-serving.md), [ADR-0107](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0107-brand-kit-visual-system.md), [web-app.md](web-app.md)).

## Remote MCP (`internal/mcpremote`)

- Serves the shared `pkg/mcptools` contract over stateless Streamable HTTP (MCP `2026-07-28`) as an OAuth 2.1 resource server with Protected Resource Metadata (RFC 9728) ([ADR-0077](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0077-remote-mcp.md)).
- Mounted on `--role=api` when both `IPSO_MCP_ISSUER` and `IPSO_MCP_RESOURCE_URL` are configured (off in local Compose because Dex does not support Client ID Metadata Documents).
- Enforces PKCE S256 + Client ID Metadata Documents at startup, separate read/propose scopes, audience separation from API tokens, role policy checks, action logging with human sponsor, 10s deadline, and a dedicated per-tenant rate limiter.
- Rejects `checks.evaluate` so repository code remains local ([ADR-0006](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0006-local-first-evaluation.md)).

## Background worker (`internal/worker`)

- Runs on River inside PostgreSQL (schema `river`, MPL-2.0 unmodified module allowed in `ci / licenses`) with no external broker ([ADR-0096](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0096-river-job-runtime.md), [ADR-0097](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0097-the-worker-role.md)). Opens no listener; writes a heartbeat file checked by `ipso-server probe`.
- Job payloads carry only the tenant ID; errors store only operation and SQLSTATE class. Because `ipso_app` owns no tables, River's reindexer is disabled (vacuum/reindex `river.river_job` operationally).
- **Jobs:**
  - `waiver_notices`: hourly + startup, deduplicated per tenant, writes due 14/3/0-day waiver expiry notices ([ADR-0054](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0054-waivers-with-expiry.md)).
  - `premise_sweep` / `premise_probe`: hourly + startup, queues due probes (4 probe workers) via `pkg/premisecheck` against tenant-allowlisted hosts only; never sends auth/cookies, never stores response bodies, never mutates decision versions, and opens review reasons on `fail` ([ADR-0053](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0053-decision-premises.md), [ADR-0098](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0098-the-premise-sweep.md)).
  - `tenant_export_sweep` / `tenant_export`: runs every minute to pick up queued tenant export requests and build encrypted export bundles ([ADR-0111](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0111-tenant-export-download-from-the-web-app.md)).
  - `chat_digests`: hourly + startup, posts waiver and premise digests to allowlisted Slack/Teams webhooks when licensed (no-op in community builds; never names people or logs webhook URLs) ([ADR-0138](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0138-slack-and-teams-notifications.md)).

## Webhooks and Terraform run tasks

- **GitHub App (`ipso-server webhooks`):** Validates decision files on `pull_request` and `push` events (`ipso / decisions` check run), requires tenant installation bindings ([ADR-0061](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0061-github-app.md), [ADR-0101](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0101-installation-tenant-mapping.md)), unbinds on verified uninstall ([ADR-0125](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0125-installation-unbind-on-uninstall.md)), and verifies exact App permissions (`checks:write`, `contents:read`, `metadata:read`, `pull_requests:write`) at startup. When `IPSO_GATEWAY_CONFIG` is set, extracts pending decision proposals from merged PR discussions ([ADR-0103](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0103-pr-proposals-in-the-webhooks-process.md)). See [github-app.md](github-app.md).
- **HCP Terraform run tasks (`ipso-server runtasks`):** Verifies HMAC signatures and evaluates plans in memory against a signed policy bundle ([ADR-0065](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0065-hcp-terraform-run-task.md), [hcp-terraform-run-task.md](hcp-terraform-run-task.md)). Logs hold only plan hashes and verdict counts.

## LLM gateway, proposals, and evals (`internal/llmgw`, `internal/proposals`, `internal/evals`)

- **Gateway (`internal/llmgw`):** Single outbound path for model calls, configured via JSON and `IPSO_LLM_*` env vars ([ADR-0081](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0081-llm-gateway.md)). Operator routes must be EU-resident (Mistral EU, Bedrock EU, or Azure OpenAI EU; [ADR-0014](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0014-eu-only-llm-routes-by-default.md)); tenant BYOK routes require explicit `allow_non_eu` if non-EU. Enforces monthly token budgets (`llm.usage`), secret/email redaction, JSON mode ([ADR-0087](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0087-json-mode-on-chat-routes.md)), bounded response tokens and timeouts up to 600s ([ADR-0088](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0088-answer-and-wait-bounds.md)), ordered failover, no redirects, and zero prompt/response logging.
- **Proposals (`internal/proposals`):** Four-stage PR extraction pipeline (`classify`, `extract`, `dedupe`, `propose`) with outsider filtering, injection screening, secret redaction, system-prompt canary checks, and strict `pending`-only storage ([ADR-0062](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0062-pr-decision-proposals.md), [ADR-0085](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0085-decision-extraction-pipeline.md)). Also drafts candidate `agent-edit` checks vetted with `pkg/rulecheck` ([ADR-0086](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0086-llm-drafted-agent-edit-checks.md)) and serves human-approved checks on `GET /v1/accepted-checks` for `ipso deliver` ([ADR-0120](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0120-accepted-check-delivery.md)).
- **Evals (`internal/evals`):** Golden extraction (floors: 0.8 precision, 0.6 recall), prompt-injection red-team, check-drafting (floor: 0.9 proposed), template-choice (floors: 0.9 precision, 0.8 none), and proposal-relation (floors: 0.8 supersedes/conflicts precision, 0.9 valid) suites replayed deterministically in `go test ./...`, recorded live locally via `scripts/evals-local.sh` (llama.cpp), and recorded in `evals-provider` (production route on `main`) ([ADR-0082](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0082-go-eval-harness.md), [ADR-0084](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0084-prompt-injection-red-team.md), [ADR-0164](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0164-one-case-eval-gate-and-deterministic-eval-markers.md), [ADR-0165](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0165-template-check-proposals.md), [ADR-0166](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0166-eval-scores-on-the-production-route.md), [ADR-0172](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0172-proposal-relation-annotations.md), [ADR-0173](https://github.com/ipsofacto-io/ipso-spec/blob/main/docs/adr/0173-local-evals-without-github-cpu-runner.md), [evals.md](evals.md)).
